# Gustav Online resolved-context example

This is an advisory example for the judgment layer, not a versioned ACS input
schema and not a file that ACS imports or validates. The values could have
come from a persistent AIOS Space, a conversation, or a brief. After choosing
the run, use `acs init <workspace> --example gustav` and copy only the values
needed for this content workspace into its local contracts.

## Content decision

- Buyer problem: a solo founder has useful workflow knowledge but no repeatable
  path from a real question to proof-backed content.
- Offer/desired action: help the viewer choose one useful next step and start a
  bounded content system.
- Topic: from buyer question to proof-backed content system.
- Format: solo/direct-to-camera.
- Group: teach/explain.
- Promise: show how one buyer question becomes a useful, approved content
  handoff.
- Proof: a visible project contract, source provenance, approved render, and
  enabled-route manifest.
- CTA: choose one buyer question and write the smallest useful recording plan.

## Route choice

- YouTube: enabled; long-form and selected short outputs; scheduled for
  `2026-09-01T09:00:00` in `Europe/Copenhagen`.
- LinkedIn: enabled; text derivative; manual/no-date.
- Instagram: disabled; enable only when a short derivative has a clear visual
  and audience fit.
- TikTok: disabled; current buyer fit is stronger on YouTube and LinkedIn.

The schedule is an ACS-owned project intent after copying, not a post request.
ACS produces a supervised publisher handoff and keeps `external_posting` false.
